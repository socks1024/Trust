# 审批条件系统设计

> 核心目标：让玩家在审核阶段拥有更多操作空间，从"批准/拒绝"的二元选择扩展为"以什么条件批准"的策略决策。

---

## 一、系统概述

在申请表下半部分新增**审批条件区**，玩家批准贷款时可以调整两个维度：

1. **利率挡位**：选择低 / 中 / 高三档利率
2. **抵押要求**：勾选申请者的一项或多项资产作为抵押物（或不要求抵押）

条件越苛刻，银行的保障越大，但申请者可能认为条件不合适而**主动拒绝贷款**。

### 设计原则

- 利率和抵押**不影响还款概率**——还款概率纯粹由申请者自身条件决定
- 利率和抵押**影响成交概率**——条件过于苛刻时，申请者会拒绝贷款
- 玩家需要在"风险保障"和"成交率"之间做权衡

---

## 二、利率挡位

### 界面设计

在贷款信息区新增利率挡位选择，提供三档按钮：

| 挡位 | 利率 | 说明 |
|------|------|------|
| 低息 | 5% × 周期乘数 | 薄利，吸引优质客户 |
| 标准 | 10% × 周期乘数 | 默认值，平衡收益与风险 |
| 高息 | 15% × 周期乘数 | 高收益，但可能吓跑客户 |

### 实时联动

玩家切换利率挡位时，表格中以下字段实时更新：

- 实际利率
- 最终利息
- 到期还款金额

### 与还款概率的关系

**利率挡位不影响还款概率。** 删除原文档中"第8项 利率挡位修正"（低+0.03 / 中0 / 高-0.03）。

## 三、抵押要求

### 界面设计

在审批条件区显示申请者的资产列表（复用资产明细区数据），每项资产旁有一个复选框（CheckBox）。玩家可以：

- **不勾选任何资产**：不要求抵押（默认）
- **勾选一项或多项资产**：要求这些资产作为抵押物

无资产的申请者不显示抵押选项。

### 违约时的效果

| 情况 | 违约损失 |
|------|----------|
| 无抵押 | 损失全部本金 |
| 有抵押 | 损失 = 本金 - 抵押物变现总价值 |

```
抵押物变现总价值 = 所有抵押物估值之和
```

抵押物变卖在本游戏中不需要打折，直接按照估值变卖

### 示例

| 贷款本金 | 抵押物 | 估值合计 | 变现总价值(×0.7) | 违约损失 |
|----------|--------|----------|------------------|----------|
| 50,000 | 无 | — | — | 50,000 |
| 50,000 | 货运飞船 | 12,000 | 8,400 | 41,600 |
| 50,000 | 货运飞船 + 储蓄 | 12,000 + 8,000 = 20,000 | 14,000 | 36,000 |
| 50,000 | 自有住房 | 35,000 | 24,500 | 25,500 |
| 20,000 | 自有住房 + 储蓄 | 50,000 + 5,000 = 55,000 | 38,500 | 0（全额覆盖） |

## 四、申请者接受度

### 核心概念

玩家点击"批准"后，申请者会根据玩家开出的条件（利率挡位 + 是否要求抵押）决定是否接受。条件越苛刻，拒绝概率越高。

### 拒绝概率计算

```
拒绝概率 = clamp(利率不满值 + 抵押不满值 + 个体修正, 0.0, 0.80)
```

---

### 4.1 利率不满值

申请者对利率的不满程度，取决于玩家设定的利率与申请者**期望利率**的差距，连续计算。

#### 期望利率（由还款概率决定）

每个申请者有一个隐含的"期望利率"，由还款概率线性映射：

```
期望利率 = lerp(期望上限, 期望下限, clamp(还款概率, 0.0, 1.0))
```

默认参数：**期望下限 = 1%，期望上限 = 18%**，全部 `@export` 导出。

还款概率越高的人期望利率越低（信用好→凭什么收我高息），还款概率越低的人期望利率越高（知道自己条件差→高息也认了）。

| 还款概率 | 期望利率 | 心理 |
|----------|----------|------|
| 1.0 | 1% | "我信用这么好，凭什么收我高息？" |
| 0.7 | ≈6% | "给我个合理的利率就行" |
| 0.5 | ≈10% | "正常水平我能接受" |
| 0.3 | ≈13% | "条件不好，高一点也认了" |
| 0.0 | 18% | "我知道自己条件很差，高息也认了" |

#### 不满值计算

```
超出部分 = max(实际利率% - 期望利率%, 0)
利率不满值 = clamp(超出部分 / 不满满值对应超出, 0.0, 1.0) × 最大不满值
```

默认参数：**不满满值对应超出 = 30%，最大不满值 = 0.60**，全部 `@export` 导出。

即：实际利率每超出期望利率1个百分点，不满值增加 0.02；超出30个百分点时达到上限 0.60。

#### 速查表

| 实际利率 vs 期望利率 | 不满值 | 申请者心理 |
|---------------------|--------|-----------|
| 低于或等于期望 | 0 | 没意见 |
| 超出 5% | ≈0.10 | "有点高，但还行" |
| 超出 10% | ≈0.20 | "这利率不太合理…" |
| 超出 20% | ≈0.40 | "太黑了吧" |
| 超出 30%+ | 0.60 | "抢钱呢？不借了" |

#### 博弈逻辑

- 对低风险的人（期望≈1%）收 20% → 超出19%，不满值≈0.38，很可能拒绝
- 对高风险的人（期望≈18%）收 18% → 未超出，不满值0，大概率接受
- 对高风险的人收 5% → 远低于期望，不满值0，肯定接受（但你赚得少）
- **正确策略：低风险给低息，高风险给高息**——符合现实风险定价逻辑

---

### 4.2 抵押不满值

根据所有被选中抵押物的估值总和与贷款金额的比例（覆盖率）线性计算。

```
覆盖率 = 所有抵押物估值之和 / 贷款金额
抵押不满值 = 不要求抵押时为 0
           要求抵押时 = lerp(最小不满, 最大不满, clamp(覆盖率, 0.0, 1.0))
```

默认参数：**最小不满 = 0.0，最大不满 = 0.40**，全部 `@export` 导出。

#### 速查表

| 覆盖率 | 不满值 | 申请者心理 |
|--------|--------|-----------|
| 0%（无抵押） | 0 | 没要求，没意见 |
| 10% | ≈0.04 | "押个小东西，无所谓" |
| 50% | ≈0.20 | "押的东西值不少钱了…" |
| 80% | ≈0.32 | "这几乎是我半副身家" |
| 100%+ | 0.40 | "押的比借的还多，太亏了" |

#### 策略空间

面对有多项资产的申请者：
- **只勾选低价值资产** → 覆盖率低，对方容易接受，但违约时回收少
- **只勾选高价值资产** → 覆盖率高，回收多，但对方可能拒绝
- **全部勾选** → 覆盖率最高，保障最大，但拒绝概率也最高
- **精选组合** → 在可接受的拒绝概率内，最大化回收保障

---

### 4.3 个体修正（议价敏感度）

每个申请者生成时带一个隐藏的"议价敏感度"属性，与贷款用途和申请人陈述的语气关联。

| 类型 | 修正 | 说明 |
|------|------|------|
| 急需用钱型 | -0.15 | 再苛刻也忍了，语气急迫恳求 |
| 普通型 | 0 | 正常反应 |
| 有底气型 | +0.10 | 条件不好就去别家，语气从容自信 |

玩家可以从申请人陈述的语气中推断此属性——语气越急迫的人越不会拒绝。

---

### 4.4 流程

```
玩家点击"批准"
  → 选择利率挡位 + 是否要求抵押
  → 点击确认
  → 系统计算拒绝概率
  → 掷骰子判定
     → 接受：贷款生效，进入正常还款流程
     → 拒绝：显示"申请者认为条件不合适，拒绝了贷款"，这笔贷款作废
```

## 七、申请人陈述结构化生成

### 设计目标

将申请人陈述从"一整段随机模板"改为**四段式结构化拼接**，每段从各自的模板池中随机选择。这样做的好处：

- 陈述内容与申请者实际数据**强关联**，不会出现"数据和陈述矛盾"的情况
- 玩家可以从陈述中**推断隐藏属性**（尤其是议价敏感度），增加信息博弈
- 模板池可以在编辑器中自由扩展，组合数量 = 各池大小的乘积，极大增加多样性

### 陈述结构

每条陈述由四段拼接而成，段落之间用空格连接：

```
陈述 = [基本信息段] + shuffle([财务状况段, 贷款用途段, 议价敏感度段])
```

其中**基本信息段固定在开头**（自我介绍放在最前面是自然的），后三段的顺序**随机打乱**。这样玩家无法通过固定位置判断哪段是什么信息，需要从语气和内容本身去推断。

---

### 7.1 基本信息段

将**职业模板**和**居住地模板**混合到同一个随机池中，随机抽取**一条**作为基本信息段。这样每次陈述可能侧重职业，也可能侧重居住地，更加自然多变。

#### 混合池构成

每个 `ProfessionConfig` 新增 `statement_intro_templates: PackedStringArray` 字段，存放该职业的自我介绍模板。
在 `RandomApplicantConfig` 中新增 `statement_location_templates: Array[PackedStringArray]`，按居住地枚举顺序存放。

生成时，将当前申请者对应的**职业模板池**和**居住地模板池**合并为一个临时数组，从中随机抽取一条。

#### 可用占位符

| 占位符 | 替换为 | 示例 |
|--------|--------|------|
| `{profession}` | 职业名称 | 工程师 |
| `{income}` | 年收入 | 40,000 |
| `{location}` | 居住地名称 | 中央区 |

#### 模板示例

**职业类模板**（挂在各 `ProfessionConfig` 上）：

| 职业 | 模板示例 |
|------|----------|
| 工程师 | "我是殖民地的一名{profession}，年收入大约{income}。" |
| 工程师 | "在这里做{profession}有几年了，收入还算稳定。" |
| 矿工 | "我在矿区干了好些年了，是个{profession}。" |
| 矿工 | "矿上的活儿虽然辛苦，但收入还行，一年能挣{income}左右。" |
| 商人 | "我做点小买卖，算是个{profession}吧。" |
| 农场主 | "我在边境镇种地，是个{profession}，靠天吃饭。" |
| 无业 | "我目前没有固定工作，一直在找机会。" |

**居住地类模板**（挂在 `RandomApplicantConfig` 上）：

| 居住地 | 模板示例 |
|--------|----------|
| 中央区 | "住在中央区，生活条件还不错。" |
| 星港区 | "家在星港区附近，每天看着飞船来来往往。" |
| 工业区 | "住在工业区，周围都是工厂。" |
| 矿区 | "住在矿区，离工作的地方近。" |
| 边境镇 | "住在边境镇，虽然偏远但清静。" |

#### 抽取方式

```
混合池 = 当前职业的模板池 + 当前居住地的模板池
基本信息段 = 混合池.随机选一条
```

**生成示例**：
> 可能抽到职业模板："我在矿区干了好些年了，是个矿工。"
> 也可能抽到居住地模板："住在边境镇，虽然偏远但清静。"

### 7.2 财务状况段

根据申请者的**资产负债比**（净资产 / 贷款金额）分为三档，从对应模板池中随机选择。

#### 分档规则

| 档位 | 条件 | 心理基调 |
|------|------|----------|
| 良好 | 净资产 > 贷款金额 × 0.5 | 自信，强调自己有底子 |
| 一般 | 净资产在 0 ~ 贷款金额 × 0.5 之间 | 平淡，简单带过 |
| 较差 | 净资产 < 0（负债大于资产） | 回避或轻描淡写 |

#### 模板池

在 `RandomApplicantConfig` 中新增三个模板池：

```
statement_finance_good_templates: PackedStringArray    # 良好
statement_finance_normal_templates: PackedStringArray   # 一般
statement_finance_poor_templates: PackedStringArray     # 较差
```

| 占位符 | 替换为 | 示例 |
|--------|--------|------|
| `{assets}` | 资产总额 | 50,000 |
| `{debts}` | 负债总额 | 8,000 |

**模板示例**：

| 档位 | 模板示例 |
|------|----------|
| 良好 | "手头还有些积蓄，经济状况还算宽裕。" |
| 良好 | "这些年攒了点家底，日子过得去。" |
| 一般 | "经济上说不上好也说不上差，就那样吧。" |
| 一般 | "有点积蓄，也有点欠款，勉强平衡。" |
| 较差 | "最近经济上有点紧张，不过在想办法。" |
| 较差 | "欠了些钱，但都在慢慢还。" |
| 较差 | "之前遇到点困难，现在还在缓过来。" |

### 7.4 议价敏感度段

通用模板池，按三种敏感度类型分组。生成时根据申请者的议价敏感度属性选择对应池。

在 `RandomApplicantConfig` 中新增三个模板池：

```
statement_bargain_desperate_templates: PackedStringArray  # 急需用钱型（-0.15）
statement_bargain_normal_templates: PackedStringArray     # 普通型（0）
statement_bargain_confident_templates: PackedStringArray  # 有底气型（+0.10）
```

**模板示例**：

| 类型 | 模板示例 | 玩家可推断的线索 |
|------|----------|-----------------|
| 急需用钱型 | "求求你尽快批准吧，真的等不了了。" | 语气恳求、急迫 → 不太会拒绝苛刻条件 |
| 急需用钱型 | "这笔钱对我来说是救命钱，什么条件我都能接受。" | 直接表态接受任何条件 |
| 急需用钱型 | "拜托了，我真的走投无路了。" | 走投无路 → 不会拒绝 |
| 普通型 | "希望能顺利批下来。" | 平淡，无明显倾向 |
| 普通型 | "条件合理的话，我很乐意合作。" | "条件合理" → 暗示有底线 |
| 普通型 | "期待你们的好消息。" | 客套话，无法判断 |
| 有底气型 | "我也在考虑其他几家的方案，看看哪家条件更好。" | 有备选 → 条件不好就走 |
| 有底气型 | "以我的条件，应该能拿到不错的利率吧。" | 自信 → 对高息敏感 |
| 有底气型 | "不着急，慢慢谈，我不缺这一时半会儿。" | 不急 → 有底气拒绝 |

---

### 7.5 生成流程

```
1. 确定职业和居住地 → 将两者的模板池合并为混合池 → 随机选一条作为基本信息段
2. 计算净资产/贷款金额比 → 确定财务档位 → 从对应池中随机选一条
3. 确定贷款用途 → 从该用途的 responses 中随机选一条
4. 确定议价敏感度 → 从对应池中随机选一条
5. 将后三段（财务、用途、敏感度）随机打乱顺序
6. 拼接：基本信息段 + 打乱后的三段
7. 替换所有占位符为实际数据
```

### 7.6 与现有系统的关系

| 项目 | 变更 |
|------|------|
| `ProfessionConfig` | 新增 `statement_intro_templates: PackedStringArray` |
| `RandomApplicantConfig` | 新增居住地模板池、财务状况三档模板池、议价敏感度三档模板池；原 `statement_templates` 废弃 |
| `LoanPurposeConfig` | 复用已有的 `responses` 字段，无需修改 |
| `ApplicantData` | 新增 `bargain_sensitivity: int` 字段（0=急需, 1=普通, 2=有底气），用于接受度计算 |
| `random_applicant_config.gd` | 第11步"生成申请人陈述"改为结构化拼接逻辑 |
| 手工配置的教程申请者 | 不受影响，`statement` 字段仍为手写文本 |

### 7.7 组合多样性

假设每个池有 3~5 条模板：

```
组合数 = 基本信息混合池(职业3+居住地3=6) × 财务模板(4) × 用途模板(3) × 敏感度模板(3)
       = 6 × 4 × 3 × 3 = 216 种不同陈述
```

远超当前 5 条固定模板的多样性，且每条陈述都与申请者数据强关联。
